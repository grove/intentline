# Small coding-agent acceptance-planning pilot, 13 October 2026

## Closeout decision, 13 October 2026

This bounded pilot is **closed with inconclusive efficacy evidence and observed
overhead**. Every real attempt and control failure remains retained; no further
inference, retries, evaluator work or product features are scheduled under this
pilot. Its limitations do not prevent closing the development effort, but they
prevent a claim of verified planning superiority or a fully qualified blinded
comparison. Any future measurement is a separate declared study requiring its
own bounded authorization. The original strict study remains `not_run`; formal
human independence remains unverified. This closeout authorizes no publication
or release.

This exploratory pilot compares ordinary coding-agent acceptance planning with
Intentline's complete existing `intentline-plan` skill and actual CLI. It uses
the user's signed-in Codex subscription outside the coordinator sandbox; no API
project, key, spending or credential extraction. P2P is excluded. Earlier
text-only/API proposals and failed preflights remain immutable private records.
The original stricter 0.6 study remains `not_run` and is not populated from this
pilot. Uncalibrated Luna critique supports AI-only development observations;
it cannot establish broad superiority or formal human independence.

## Boundaries and continuation

Normal shell/file/search/edit/Python/Git inspection tools are expected. Native
permissions deny root reads, permit enumerated task/runtime inputs and platform
dependencies, and permit writes only in the actor's own scratch. Suppress project
AGENTS/host skills/hooks/memory/discovery and inspect retained effective instructions
and tools. Common native instruction blocks, including standing GitHub effect
permissions, remain; they do not supply Intentline/P2P acceptance guidance.
Separate sessions alone are not isolation. Private answers, checklists, labels,
other outputs and session stores remain outside each actor's readable scope.

Reuse [existing access helpers](AGENT_ACCESS_06.md) where applicable. Probe only
nonsecret canaries; retain positive reads, actual EPERM denials, identities,
mounts, inventories and every failure. Inspect file/search/image/edit and actual
app/MCP/session/delegation dispatchers. Revision 4 accepts app/MCP/delegation
capability exclusions with configuration/inventory/dispatcher witnesses; missing
paths, disabled tools, timeouts and empty inventories are not permission denials.
Provider transport is allowed, command egress is denied. Never probe real answers.

Keep actual arm mappings outside every critic-readable file, including config.
Inspect the complete actor inventory for misplaced identity metadata before
canary tests; denying a synthetic labels directory alone is insufficient.
Retain actual plan wording that affects meaning and report any remaining brand
references/format cues; anonymous filenames alone do not establish blinding.

Run the first pair and fresh Luna critique only after bounded approval/admission.
Continue the other two pairs only if models/settings/inputs, coding tools, actual
skill/CLI execution, boundaries/deadlines, complete plans/transcripts and usable
source critique are technically valid. Stop on refusal, transport failure,
timeout, missing artifacts, drift, unexpected context/model or leakage. Retain
partial attempts and mark remaining slots `not_run`. Comparative plan quality
never determines continuation or retries.

Luna must open the actual original request, TASK, catalog and every source file
listed by the manifest before assessing plans; manifest entries and plan quotations
are not substitutes for original-source reads. A failure stops continuation.
Luna receives the same packet, existing `rubric_02.md` and lossless plans under

mapping. Revealing wording stays and weakens blinding. No private checklists,
labels, prior critiques or operator history. Verify material findings against
source and plan quotations, preserving errors, alternatives and disagreements.
Do not change frozen requirements after outputs.
