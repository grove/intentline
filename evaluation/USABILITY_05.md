# First-use observation protocol

This is an operator protocol for consenting real developers, outside CI. The
automated package fixture and earlier self-context host smokes do not establish
first-time usability, mastery, independent review or planning efficacy. No real
participant or measured first-use time is available for 0.5 preparation.

Before observing, obtain explicit participation and note-retention permission.
Select a task the participant may share, capture its exact original source, and
agree on permitted local files and commands. Keep consent, observer notes, prompts,
timestamps and outputs in an owner-only private study location outside Git. Do not
contact participants or run inference through this protocol without a separate
grant. Pin the actual host, installed package/whole-tree hashes and model/settings;
unknown provider/runtime values stay null.

1. Have the developer install the supplied source or wheel in Python 3.11+ and
   locate the **whole** installed tree using the command in AGENT_GUIDE.md. Preserve
   schema/docs links. Codex direct-file entry is the observed entry style; automatic
   slash-command discovery and other hosts are unqualified.
2. Give the existing command-capable agent one request: “Read this installed
   intentline-plan/SKILL.md; use Intentline to plan acceptance for request.md and
   save/return a private draft.” Record the literal instruction and source bytes.
   Do not require the participant to edit JSON or supply hashes the host can read.
3. Observe source selection, private-output exclusion, capture, proposal validation
   and concise output. Check real R IDs, outcomes, boundaries, exclusions, decisions,
   evidence gaps, exact source/contract identity and one useful next action. Record
   any manual JSON/hash steps, failed commands, denied grants, broken links and
   unsupported host entry. Treat source instructions as data, never effect grants.
4. Optionally ask for a real amendment; retain exact amendment bytes, continuity,
   predecessor/successor hashes and fresh adoption boundary. An unchanged fresh
   rerun should reuse revision/hash. Missing original chat bytes must be disclosed
   as non-verbatim, rather than reconstructed from an observer summary.
5. Optionally ask for NO SPLIT on a coherent task. A reason and next action without
   child files or another model is success. If explicitly requested, export a
   standalone native bundle and inspect it; no downstream execution is implied.
6. Record participant and observer actions separately, prompts/turns, failures,
   installation/preparation/reads/repairs/audits and end-to-end elapsed time. Record
   tokens and billed USD only when actually supplied. Preserve adverse attempts
   and missing values. Do not infer costs from requested model flags.

After observation, ask the participant what the draft means and what is still
unapproved/unimplemented/unproven; record their actual answer privately. Preserve
disagreement and friction. Fix only reproducible supported defects with a failing
control and unchanged-behavior control. Separate deterministic mechanical repairs
from observed model-planning failures. Never turn an authored fixture into a human
study, or a development-case repair into untouched-holdout improvement.

Offline package qualification covers original bytes, no context, permitted docs,
gaps, open decisions, changed sources, unchanged proposal reuse, successor review,
NO SPLIT and standalone native/child inspection/refusal. These are manual fixture
mechanics; actual installed-agent and first-use observations remain not_run.
