# Optional acceptance-preserving slicing

A correct NO SPLIT keeps one coherent parent agreement whole, explains why direct
delivery suffices, and gives one next action. It creates no children. Invoke the
installed intentline-slice skill with one request; the agent handles JSON/hashes.
Saving a recommendation requires your explicit local record request. Manual CLI
operators can use the schema directly.

SPLIT_PROPOSED is a draft allocation of 2–8 independently observable contributions,
not child acceptance. Each qualified S#:C# traces to parent R IDs, inherits all
parent constraints and exclusions, and has public evidence or an explicit gap.
Every parent R has a named assembled-product final verifier. NO SPLIT is the default;
files, counts, difficulty, missing harness or failed implementation are not reasons
to split. Concrete interface sequencing or actual ownership may earn a boundary.
Compare the direct route and credible merges first.

`slice preview --work WORK --proposal FILE` reads canonical JSON without writes.
`slice record --work WORK --proposal FILE --expected-parent-sha256 HASH` saves
immutable advisory bytes inside WORK/slicing and writes the current pointer last.
`slice status --work WORK` and `slice render --work WORK` read current applicability
and retained disputes. Same-parent changes explicitly supersede the prior digest
and explain new evidence. History is bounded at 256 records, without truncation.
NO SPLIT uses zero children, allocations, prerequisites and parent_final_checks.

The parent binding includes canonical contract/source hashes, full source-chain
hash and continuity digest (null for original work). Canonical JSON sorts keys,
uses compact separators, exact UTF-8 and one final newline. Preview/record normalize set-like ID arrays,
children, criteria, allocations, qualified contributors, boundaries and citations
lexicographically with unique identities. Immutable records and exports require
that normalized order; equivalent proposal reordering reuses the same digest. Quotes retain exact saved source text.
Unknown fields, unsafe Unicode controls, unrelated source refs, dropped boundaries,
unsupported recursive children, unsafe files and stale sources refuse.

`slice audit-record --work WORK --report FILE` optionally retains actor-unverified
source-cited reports. Favorable reports erase no adverse findings. No audit stage
is mandatory. Structural validation never establishes semantic completeness,
authenticated independence, approval, implementation or parent proof.

`slice impact --work OLD --successor-work NEW` compares verified revision and
successor lineage read only. Changed source identities require fresh allocation
review, even for mechanically unchanged candidate IDs; constraints/shared state
and prerequisite changes conservatively affect dependent children. Missing or
unrelated continuity blocks rather than guessing. A→B→A never transfers authority.
The comparison leaves external implemented work, issues and PRs untouched.

Resource bounds: 2 MiB per file, 256 rows per new array, 64 refs/contributors,
8 children, 56 prerequisite edges and 256 historical plans/audits. Excess refuses.
Windows retains exit 3 before record I/O. POSIX owner-only local storage coordinates
cooperative writers; owner-resistant tampering, network filesystems and power-loss
durability remain unqualified. Hashes bind bytes, not people or permissions.
